# Phase7 decisions

> BCC Phase 7 Billing & tiers — agreed Stripe architecture, pricing and tier contents

Phase 7 (Billing & tiers) started 2026-07-12. Two planning popups agreed with Phil.

Architecture (popup 1): one Stripe Customer per company. Subscription tiers = a licensed BASE price per tier PLUS a separate £5/seat licensed price, quantity = max(0, active users − 4) (maps to computeSeatUsage in lib/billing/seats.ts). Diamond = NO subscription, usage-only via monthly Stripe invoice items built from usage_monthly (SMS+AI). Black = NO Stripe objects, free-everything, founder-granted. Card capture = Stripe Checkout + Customer Portal only, we never touch card data. Proration = Stripe default create_prorations (mid-month seat change prorates onto next invoice). Activation = Founder sets tier at company creation; Company Admin self-serves the card via Checkout on /settings/billing and self-manages in the Portal; Founder keeps visibility + grants Black/Diamond. Billing page = /settings/billing (extends the Seats card). Webhook = /api/webhooks/stripe (already in PUBLIC_PATHS via the /api/webhooks prefix). GBP only, no trials.

Pricing (popup 2, researched vs UK care software £100–£350/site/mo): Business £49, Pro £99, Enterprise £199 monthly base, all + 4 users then £5/extra. Tier contents = FEATURES LADDER: all tiers core compliance (People + Service Users, checks, forms, RAG, email digest, 1 branch; extra branches a paid add-on all tiers). Pro adds SMS + reporting/inspector exports (Phase 8) + form builder. Enterprise adds AI (policy parse, future AI form gen) + integration layer + priority support. Monthly only for now (annual deferred).
