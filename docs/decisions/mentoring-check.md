Model = a plain People check_definition, no new complete-flow code:
- migration 0122: seeded forms(key 'mentoring', population people) + form_versions v1 published holding the schema; one check_definition recurring=false, anchor='completion', frequency/interval null, **schedule_mode='ad_hoc'**; backfilled 40 blank-due check_instances (active Acme people).
- Had to widen the CHECK constraint: `check_definitions_schedule_mode_check` only allowed 'interval'/'after_sup3'; 0122 drops+recreates it to also allow 'ad_hoc'.
- Code: added `"ad_hoc"` to CheckDefinition.schedule_mode union (lib/people/types.ts) and `if (def.schedule_mode==='ad_hoc') return "Ad hoc"` in recurrenceLabel (lib/people/logic.ts). Nothing else needed — the record page Checks section renders ALL non-supervision defs as tiles (otherDefs = definitions minus 'supervision'), so mentoring auto-appears; the register matrix only shows CURATED_CHECK_KEYS + parked extra-columns, so it does NOT appear there.

Why ad-hoc "just works" on People: check_rag(null due)='none' (people view has no non-recurring-green special case, unlike SU), so before AND after completion rag='none' → ragPill renders neutral "Not scheduled", and 'none' is excluded from the person_rollup red/amber/green counts so mentoring never drags anyone's status. complete_check for a People one-off nulls due_date; nextDueAfterCompletion returns {nextDue:null} for !recurring. The Complete link only checks `s && form_id && canComplete` (not rag), so it persists → repeatable, each submission adds evidence + restamps last_completed_on (visit_date is the first date field = completion stamp).

Form = 8 sections + Declaration (~40 fields): visit_details (supervisor_name, visit_date, mentoring_started/finished as short_text time), Section One arrival (uniform_policy/addressed_by_name/valid_id_badge Y/N + if-no long_text), Section Two care plan (checked_visit_notes, knows_care_needs, ppe_used_correctly[Y/N/NA], manual_handling_equipment[NA], food_handled[NA], working_area_tidy, ppe_disposed[NA]), Section Four medication (med_consent/med_six_rights/mar_completed all Y/N/NA), Section Five attitude (communicated_compassion, respected_dignity, enabling_way, sent_observation + observation detail visibleWhen yes), Section Six recording (accurate_record), Section Seven mentor feedback (su_willing_feedback gates needed_prompting/carer_openly_communicated + their comments via visibleWhen yes; areas_improvement_needed + comment), Section Eight follow_up_actions, Declaration (declaration_date). "Thistle Care" in the uniform-policy question was rewritten to "Acme Care Company".
