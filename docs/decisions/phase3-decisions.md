# Phase3 decisions

> BCC Phase 3 (People section) agreed scope decisions from popups 2026-07-08

Phase 3 = People section. Scope agreed with Phil by popup on 2026-07-08 (all recommendations, plus he shared his live Monday board "Team Compliance NP / Compliance Matrix" as the target look):

- **Person record fields = identity + employment only.** full name, job title, branch (required), employment status (active/leaver), start date, leaver date, work email, mobile. Plus optional person-assignment fields seen on his board: line Manager, Team Leader (TL), Team. DBS, right to work, training refreshers etc. are all Checks, never record columns, so everything flows through the one compliance loop + RAG. Kept distinct from Service Users in UI and data model.
- **Check model = definitions + per-record instances.** `check_definitions` per company (name, linked Form or capture kind, default recurrence, amber override, applies-to people) -> `check_instances` per record (due_date, status, last_completed). One-off (non-recurring) checks supported (e.g. probation / 3-month review).
- **Two check kinds:** (1) Form-completion checks satisfied by completing a seeded Form -> Evidence (supervision, appraisal, spot check, competency); (2) document/date checks satisfied by recording a renewal/expiry date + optional upload, **expiry-anchored** (DBS, Enhanced DBS, Right to Work, Manual Handling refresher). Both produce Evidence.
- **Recurrence anchor = actual completion date + interval** (drift-free; supervision done today -> +interval). PLUS **expiry-anchored mode**: due = document expiry date minus a lead time (right-to-work follows a visa expiry, DBS a set cadence). This is the "Monday-automation" behaviour Phil asked for: completing/renewing auto-advances the check to its next cycle. Recurrence rule shape: { frequency: day|week|month|year, interval:n, anchor: completion|expiry, leadDays? }.
- **Recurrence engine = one shared unit-tested module (lib/recurrence).** Europe/London, month-boundary maths (31 Jan +1mo -> 28/29 Feb), leap years, DST. Clears the recurrence date-maths item logged to Final Testing.
- **RAG amber threshold: company default 30 days, overridable per check definition.** compliant green / due soon amber / overdue red. Server-computed for correctness.
- **Rollup check -> record -> register -> branch -> company dashboard: server-computed RAG + shared Supabase Realtime helper** (unfiltered subscribe, REPLICA IDENTITY FULL, poll fallback), mirroring Phase 1 realtime gotchas. Also clears the parked Additions "live-updating list" item.
- **Default recurrences (cited sector norms, editable per company): Supervision 3mo, Appraisal 12mo, Spot Check 3mo, Competency 12mo; DBS renewal ~36mo (expiry-anchored), Right to Work expiry-anchored, Manual Handling refresher 12mo.** CQC sets no fixed cadence. Definitions **auto-apply to each new Person from start date, idempotent** (applying twice never duplicates).
- **Register presentation = dense compliance matrix** like his Monday board: sticky left Carer column (name+avatar), core employment columns (Manager, TL, Team, Working Status, Start Date), then ONE RAG-coloured cell per Check (next due, last completed beneath). Sort/filter/group, status pills, horizontal scroll on desktop, stacked cards on mobile. Dark navy/gold, canonical controls only. **One column per Check (not Sup 1/2/3); full cycle history in the record drill-down** (Monday fakes cycles with columns; ours auto-cycles).
- **Leavers + archived excluded from active register, rollups, reminders, reports;** separate Leavers/archived filter view for audit history. Completed check = green + completion date, never "outstanding". Empty states on register + each record.
- **Permissions (RLS-enforced):** Manager = full register for their branch(es); Supervisor = only assigned caseload (via `person_assignments` table); Team Member = only their own linked record (profile linked to a Person via `person.profile_id`); Admin/Platform = all. Tighten Phase 2 evidence reads to match now records exist. (Standing rules from [permission-boundaries](permission-boundaries.md).)

Research cited (present-day, July 2026): CQC Single Assessment Framework fully operational across providers by end 2026, quality statements replace KLOEs, inspectors want supervision/training/competency/recruitment records; **no CQC-prescribed supervision cadence** (sector norm quarterly supervision, annual appraisal). **DBS: no statutory expiry**; CQC providers typically renew every 1-3yrs or use the Update Service (£16/yr). **Right to work: follow-up check before time-limited permission expires** (record expiry date, set reminder); single check suffices for settled/pre-settled.

Build order: recurrence engine (+tests) -> migration 0004 (people, check_definitions, check_instances, person_assignments, RAG view/fns, RLS, seed people catalogue) applied to ref bgrtcvyjuwopunpnudeu ONLY -> register matrix UI -> record drill-down -> check config/assignment -> complete-Form-satisfies-Check via submitEvidence(record_type='person') -> RAG rollups + realtime -> leaver/archived exclusion -> deploy + test checklist.
