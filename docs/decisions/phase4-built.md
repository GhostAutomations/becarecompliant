Key decisions (Phil, kickoff 2026-07-09/10):
- Schema = "same as People": SU checks + evidence reuse the SHARED check_instances + evidence tables (record_type already supported 'service_user'). 0027 adds check_instances.service_user_id + parallel SU views (service_user_check_status(_all), service_user_rollup(_all)) + RPCs (apply_service_user_checks, can_manage/can_complete_service_user, is_service_user_supervisor) + service_user_assignments + service_user_trackers. complete_check was GENERALISED to authorise either population (person_id vs service_user_id) — one shared RPC, backward compatible.
- Planned Review Date is a BOOKING: click cell -> date + reviewer selector -> sets planned_review_date + planned_reviewer_id on service_user_trackers, derives Review Status to "Booked In". Completing a Care Plan Review clears the booking.
- The reviewer calendar-invite EMAIL (.ics via Resend) is DEFERRED to Phase 6 (Phil: "booking now, email in Phase 6, remember to come back and test"). Logged in Phase 6 + Final Testing.
- Review Status AUTO-DERIVED (lib/service-users/logic.reviewStatus): Overdue when New Review Due passed; Booked In when Planned Review Date set and not overdue; else Awaiting Review. It is a read-only pill, NOT an editable dropdown (supersedes the brief's "pill dropdown" wording).
- SU review defaults (editable, cited): Care Plan Review 12mo, Risk Assessment 12mo, MAR Audit 1mo, Consent Review 12mo, amber 30. SU checks auto-schedule from package_start_date + interval on add (unlike People, which start most checks blank) so RAG is accurate from day one.
- Team Member SU isolation is STRICTER than People: NO branch-wide Team Member read for Service Users; a Team Member sees a SU only when explicitly assigned (service_user_assignments / is_service_user_supervisor). No is_branch_team_member path in SU RLS.

COMPLEX BRANCHES (Phil, 2026-07-10, post-launch iteration): each branch has a service_user_type Simple|Complex (branches.service_user_type, migration 0033, default simple; set in Settings > Service Users Type; office/team excluded everywhere in SU). SU register has NO "All branches" — always one branch, columns follow that branch's type. Simple = the 4 review columns (Most Recent Review / New Review Due / Planned Review Date / Review Status). Complex = 8 columns REV1-4 DUE/COMP instead. Complex runs 4 rolling Care Plan Reviews at an 80-day cadence (companies.complex_review_interval_days, migration 0034, default 80, editable in Settings): Review 1 due = package start + interval; Review n due = Review(n-1) completion + interval. Review slots are POSITIONAL (reviewSlots in lib/service-users/logic.ts): derived from the ordered list of ALL care_plan_review completions (reviewComps = string[], oldest first), NOT keyed by review number. Cycle of `count`(4): completedCycles=floor(n/4), cycleBase=that*4, cycleComps=slice(cycleBase), anchor=cycleBase>0?comps[cycleBase-1]:packageStart; Review i comp=cycleComps[i-1], Review i due=(i==1?anchor:cycleComps[i-2])+interval. So completing Review 4 restarts the cycle (Review 1 due = last completion + interval). Positional is deliberate so switching a branch Simple<->Complex reuses the same completions: Simple->Complex fills Review 1-4 from existing completions; Complex->Simple, Most Recent Review = last completion. Reviews complete IN ORDER: drill-down shows a Complete button only on the next outstanding slot; the care_plan_review form's review_number field (migration 0035, still present, optional) is always hidden (removeField) and unused. On branch type switch, setBranchServiceUserType calls reschedule_branch_reviews RPC (migration 0037) to re-anchor every SU's care_plan_review due_date to the new interval (Complex interval vs care_plan_review def interval 365) = coalesce(last_completed_on, package_start)+interval, keeping the RAG rollup correct. completeCheck advances care_plan_review by the complex interval on Complex branches. Complex drill-down shows 4 Review slot cards like Supervision; Simple keeps the single review card. New: components/service-users/{branch-type-form, complex-interval-form}.
