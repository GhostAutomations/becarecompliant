# Rtw ai questions

> Phil wants the Return to Work QUESTIONS generated per absence by the AI, not fixed schema fields — the conflict with immutable Evidence and the way round it

Phil, live test 2026-07-27, on the v2 form: "I wanted those question fields generated by
the ai when they press 'draft it for me' as not every absence will be the same."

So the fixed question fields built in v2 are not what he wants. He wants the AI to
produce questions TAILORED to this absence, rendered as proper separate inputs to
complete, not one text box (that part of his original ask still stands).

## The conflict, and it is real

Evidence is immutable and pins a `form_version` id, and the server validates answers
against the STORED published schema (`lib/form-validate.ts`). Fields that only exist
because an AI invented them seconds ago are not in that schema, so they cannot be
validated or stored as ordinary answers. Generating a new form version per absence is
not an option either: versions are the audit trail.

## The way round it (recommended, not yet agreed with Phil)

Keep ONE field in the published schema, e.g. `tailored_questions`, holding a structured
list of question/answer pairs. Then:
- `draftReturnToWork` returns a small JSON array instead of prose: each entry a question,
  a type (`text` / `yes_no` / `choice` with options), and an empty answer.
- The dialog renders that array as REAL inputs, so Phil gets separate, clearly
  completable fields that differ per absence.
- On save the array (questions plus the answers given) is stored in that one schema
  field, so Evidence stays valid, the form version is untouched, and the record shows
  exactly what was asked and answered.
- The Evidence PDF renders the pairs as a question and answer list.

Keep the small fixed core that is genuinely always asked (fit to return, work related,
adjustments, support agreed) as normal fields. The AI set sits alongside as the tailored
part. Also keep the guardrails already in the prompt: never diagnose, never speculate
about a medical cause, never suggest an outcome.

## Decide with Phil before building

Whether the AI questions REPLACE the six fixed question fields added in v2, or sit
alongside them. Recommendation: replace them, keeping only the core four above, or the
form gets long and repetitive.
