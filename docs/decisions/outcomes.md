# Outcomes

> BCC Outcomes sub-department (Service Users): personal outcomes -> PQS %; agreed design + build progress

Outcomes = a sub-department under Service Users (nav: Service Users > Outcomes, /service-users/outcomes was a placeholder "coming later"). Purpose: capture each service user's PERSONAL OUTCOMES (Welsh well-being / CIW outcomes framework — "what matters to me") and roll up the % achieving or progressing for the PQS (Cardiff/LA Provider Quality System return, see [cardiff-pqs](cardiff-pqs.md)).

DESIGN AGREED (Phil, 2026-07-21, all recommended): (1) per-SU LIST of outcome statements, each with a STATUS = Achieved / Progressing / Working towards / No longer relevant, + last_reviewed date + review note; (2) recurring OUTCOMES REVIEW with RAG due dates (like care plan reviews), completing it stored as Evidence; (3) Outcomes overview page = register of SUs + outcomes status + headline PQS % (achieving or progressing), exportable PDF/CSV.

PQS rule: an outcome is IN SCOPE unless "no longer relevant"; "achieving or progressing" = Achieved or Progressing. % = achieving-or-progressing / in-scope.
