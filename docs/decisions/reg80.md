# Reg80

> Regulation 80 (RISCA Wales) six-monthly Quality of Care Review report, built on the Reg 73 engine

Reg 80 = the RISCA **Quality of Care Review** (six-monthly, per branch, prepared by the Responsible Individual). Sister to [reg73](reg73.md). BUILT + fully critiqued/PASSED 2026-07-31 (migration 0158 `reg80_reviews`). Reuses the Reg 73 engine wholesale (form/signature/PDF/AI/reports-manager patterns), so all the Reg 73 fixes were baked in from the start.

STATUTORY BASIS CHECKED (Phil: "check with the CIW"): Regulation 80 of the Regulated Services (Service Providers and Responsible Individuals) (Wales) Regulations 2017 (legislation.gov.uk/wsi/2017/1264/regulation/80). It requires the review to analyse aggregated INCIDENTS, NOTIFIABLE INCIDENTS, SAFEGUARDING, WHISTLEBLOWING, concerns and complaints, review action on complaints, consider record-accuracy audits, and the report must contain an ASSESSMENT OF THE STANDARD OF CARE + RECOMMENDATIONS. Phil's own template lacked incidents/safeguarding/whistleblowing + an explicit overall assessment, so those sections were ADDED (manual narrative for the ones we hold no data for). Lesson: for any regulator report, verify the statute, do not just mirror the customer's document.

FILES: lib/reg80/{prefill.ts, spec.ts (REG80_SECTIONS + buildInitialData + reg80DataSummary; REG80_AI_FIELDS/REG80_DATA_FIELDS/REG80_IMAGE_FIELDS derived from `ai`/`data`/type flags), data.ts (reuses listReg73Signatories), actions.ts, pdf-doc.ts}; components/reg80/{reg80-form.tsx, reg80-image-input.tsx, start-review-button.tsx ("Run R80"), reg80-reports-manager.tsx} + reuses components/reg73/{reg73-signature, signature-pad}; app/(app)/reports/reg80/{page,[id]/page,reports/page}; app/api/reports/reg80/[id]/pdf/route.ts; card in reports-panel (Pro-locked). Roles: RI + admins + registered_manager edit, manager views.

DATA REUSE (per branch, no parallel logic): getPqsMeasures (training/supervision/care-plan/satisfaction/outcomes/SCW rates); person_check_status rag='red' for overdue Supervision/Spot Check/Manual Handling/Medication Competency/Mentoring; complaints by `formality` (Informal/Formal) + `concern_type` over 6 AND 12 months; people turnover from `start_date` + `leaver_date` + `employment_status='leaver'` (care/office split by job_title heuristic); Audit COMPLETION counts from `evidence` where form_id in the company's `check_definitions` key='audit' (by record_type person/service_user), against a 5/month target; outcomes from `service_user_outcomes` (SU with an outcome vs active SU); raw SCW from `people.scw_registration_number`.

PERIOD DRIVES THE FIGURES (Phil: "if i change the dates and refresh, doesnt the narrative change?"): getReg80Prefill takes an optional `period {start,end}`; all windowed queries bound to it (default last 6 months). Refresh data passes the form's current date inputs (read by id f_period_start/f_period_end), re-pulls for those dates, updates the data boxes IN PLACE, then a gold banner ASKS "Update the narrative from the new figures?" (Update narrative reruns the AI draft, Keep mine leaves edits). AI never auto-overwrites narrative.

LESSONS (permanent):
1. IMAGE UPLOAD, two fields, one deterministically failed. Optional images (survey chart, call-duration table) stored as downscaled JPEG data URLs in `data` jsonb (bounded to 1200px both dims, q0.78). The label-WRAPPED hidden file input worked for one field (call_durations_image) but the survey field (su_survey_image) captured NOTHING every time (DB confirmed: key present, value ""). Root cause never seen live (Chrome disconnected), diagnosed from the DB. FIX that worked: a STANDALONE `<input type=file hidden>` triggered by a `<button onClick={()=>inputRef.current.click()}>` instead of wrapping the input in a `<label>`. Use the button+ref pattern for file pickers, not label-wrapping. Also: block submit while any image is still decoding (parent counts `imagesBusy` via an onBusyChange callback) so a fast submit can't drop an image whose hidden input is still empty.
2. SUBMIT ERROR PLACEMENT. The submit button sits at the BOTTOM (Sign off box) but the error span was only in the TOP toolbar, so a validation refusal (no signature) looked like "nothing happened". FIX (reg73 AND reg80): show submitState.error next to the Save and submit button; top toolbar shows only its own actions' errors. Error red brightened to `text-red-400 font-semibold` (Phil: "i need the red to be brighter").
3. PDF image block: the shared renderer (lib/export/pdf.tsx) forced height when none given, squashing content images. Now it only pins height when explicitly set (signatures 220x64); content images pass width only and keep aspect ratio.

Reg 73 and Reg 80 cards share one row in /reports (reordered so they pair; Training report moved below). Nav: the Acme "navy" rail opens the drawer ON HOVER now (navy-nav onMouseEnter setOpen, per-icon onMouseEnter openOn), closes 60ms after leaving.
