# On call

> On Call department (Additions) + new on_call user role: rota + call log, Pro-gated; on_call role limited to On Call/Absence/Complaints across all branches with roster read; migrations 0113/0114

Built 2026-07-23 (Phase 10 Additions). On Call is a top-level department (like Complaints): a **rota** (on_call_shifts: start->end datetime, on-call person + phone, branch) and a **call log** (on_call_logs: per-company ref number, caller, category, details, action, outcome, follow_up_required/done flag). Log/register model, NO RAG. Pro-and-above (Feature "on_call" in lib/billing/tier PRO_FEATURES; nav gated in app/(app)/layout.tsx like planner). Datetimes stored/displayed as stable UTC wall-clock (lib/on-call/format.ts) to avoid DST drift. Files: lib/on-call/{types,data,actions,format}.ts, components/on-call/{rota-view,shift-form,log-register,log-form}.tsx, app/(app)/on-call/{page, log/page, log/new/page, log/[id]/page}.tsx, app/api/on-call/export/route.ts (CSV). Realtime on both tables.

NEW ROLE **on_call** (Phil, decided in popups): a focused out-of-hours role whose ONLY departments are On Call, Absence and Complaints, across ALL branches of their company, FULL use (create/edit). No Dashboard (home = /on-call). Invite-selectable ("On Call" option). ROLE_LABELS.on_call="On Call". Bespoke flat nav via navEntriesForRole special-case (On Call / Absence / Complaints only) so the People parent never shows. Redirects added: /people, /people/holiday, /service-users, (training bounces via /people) all redirect on_call -> /on-call; dashboard redirects on_call -> /on-call.

RLS (migration 0113): helper `is_company_on_call(cid)` (role='on_call', company match, active) added ONLY to on_call_shifts/logs, complaints (select/insert/update), complaints_config(select), complaint_responses(select/insert), absence_events/meetings(select/insert), absence_config(select), evidence_select (record_type='complaint' only), and submit_evidence branch guard (`is_branch_member OR is_company_on_call`). Dept-access predicate on the on_call tables = platform_admin OR is_company_wide OR is_branch_manager OR is_branch_supervisor OR is_company_on_call (i.e. Supervisors and above + on_call). Also recreated is_branch_supervisor defensively. Migration 0114: widened people_select with is_company_on_call so the ROSTER loads (Absence needs to pick a staff member) — Phil chose "roster read only", NOT the People compliance department (hence the /people redirect). Complaints/Absence page role gates (MANAGE_ROLES / canManage) also got "on_call" added in the app layer.

ROTA REDESIGN 2026-07-23 (migration 0115): the rota is now a 3-week grid (weeks labelled Current / +1 / +2), Monday->Sunday, TWO slots per day AM (00:00-12:00) / PM (12:00-24:00). Each cell = one on_call_shifts row (shift_date + slot columns added; starts_at/ends_at kept, derived from slot). Per-company setting companies.on_call_rota_scope ('branch'|'company', default 'branch'; Acme=9d7d082b set to 'company'): company scope = one branch-less rota (branch_id NULL), branch scope = one grid per branch with a selector. Two partial unique indexes enforce one assignment per cell. RLS recreated to allow NULL branch (company-wide seniors + on_call manage any; branch mgr/supervisor manage their branch). New code: lib/on-call/format.ts threeWeekGrid/dayHeading/slotInstants; data.ts getRotaScope/getRotaGrid (returns Map date|slot -> RotaCell); actions.ts assignSlot/clearSlot/setRotaScope; components/on-call/rota-grid.tsx (grid + admin By company/By branch toggle + click-cell editor). Old rota-view.tsx/shift-form.tsx now unused (kept). Admin-only scope toggle on the page.

LOG-A-CALL DRAFT 2026-07-23 (migration 0116): the "Log a call" form autosaves per user (server-side table on_call_log_drafts, one row/user, RLS user_id=auth.uid, jsonb data) so an in-progress call survives logout/device change; reads ignore drafts >12h old; cleared on submit (createLog deletes the row) and via clearLogDraft(). LogForm gained a `draft` prop (new-call page passes getLogDraft(user.id); edit/drill-down omit it -> drafting off); prefills from draft and debounce-autosaves (1s) via saveLogDraft. Also this session: rota heading renamed "Rota", removed top-right Call log button + call-log Back link + call-log follow-up filter + CSV export button; week date-ranges removed.

LOG FORM = PER-SHIFT (migration 0117, 2026-07-23): the "Log a call" form is now a per-shift record. Fields: Branch (only shown when rota scope='branch'; company scope -> branch_id NULL, on_call_logs.branch_id made nullable + RLS recreated null-safe), Shift dropdown (AM/PM: DD/MM/YYYY, value `${slot}|${date}`, options = yesterday/today/tomorrow, default = current shift), On Call Notes (details, required), Number of complaints + "Have these been logged?" yes/no (complaints_count/complaints_logged), Number of absences + yes/no (absences_count/absences_logged), Needs Urgent Follow Up (follow_up_required) + notes. Removed: handler-by (handler = created_by/current user, set server-side), category, handler name, caller name, caller-was-a, related service user (columns kept, nulled). Register shows Ref/Shift/[Branch if any]/Notes/Complaints/Absences/Urgent. DASHBOARD: manager+ ("On Call: urgent follow-ups") shows a card per open urgent follow-up (shiftLabel + branch) linking to /on-call/log/[id]; getUrgentFollowUps() in on-call/data. Draft autosave (0116) still applies to the new form.
