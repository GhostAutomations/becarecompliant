# Record updates

> The Updates section on People and Service User records (like Monday's updates), Phil's agreed design 2026-09-24. Read before touching record updates, mentions or the SU record check row layout.

- [stated] Called "Updates" (Phil preferred it over "Notes"). On both People and Service User records.
- [stated] People record: a tile next to the Complaints tile, in the row above Holiday. Shows count plus pinned (else newest) update preview; "Open" shows the full thread in a centre popup like Evidence history.
- [stated] Service User record: Updates tile next to Audit, exactly above History; make the Setup Visit and Audit tiles smaller so the two sit exactly above Evidence history.
- [stated] Who: Supervisor and above who can see the record read and post; Viewer reads only; On Call and carers never. Managers/Supervisors do NOT see Updates on their own Person record.
- [stated] Editing: author can edit own, shows "Edited", original kept; only a Company Admin can remove, with a reason, leaving a "This update was removed" line.
- [stated] Features in v1: replies, attachments (JPG, PNG, HEIC, PDF, DOCX, XLSX; 5 per update, 20 MB each), @mentions with email, pinning. Anyone who can post can pin.
- [stated] @mention: only people who can see the record can be tagged; branded email with an Open the record button, never the update's text.
- [stated] Updates tile must be the same height as the Audit tile beside it (uniform row).
- [stated] Whiteboard To book tiles: fixed Monday to Sunday weeks, this week first, not rolling ("I want set dates"); a check due earlier this week and unbooked stays in the first tile, date in red.
- [stated] Updates retention: "Build it next" (2026-09-24) — built as 0325, updates erased on the evidence retention clock (8 years after end of care, never on hold).
